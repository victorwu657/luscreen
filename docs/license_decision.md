# LuScreen 许可证选择结论与理由

## 结论

本仓库选择使用 **AGPL-3.0-only** 作为开源许可证，并配套提供 **商业授权（Commercial License）** 作为企业闭源使用的替代方案（见根目录 COMMERCIAL_LICENSE）。

## 选择理由（不少于 300 字）

从你的目标来看，核心诉求有两点：第一，个人用户可以免费使用/修改/分发；第二，任何修改与再发布必须保持同许可证并继续开源（“传染性”）。在候选许可证中，AGPL-3.0-only 在“强制开源二次分发”维度表现最好：它属于强 copyleft，并且对“通过网络向用户提供服务”的修改版也要求提供对应源代码，这一点能有效避免常见的“只部署不分发、因此不公开修改”的漏洞（AGPL 的设计目的之一就是覆盖网络服务场景）。这一点非常贴合你希望的“修改或再发布必须继续开源”的要求。

同时，你希望“企业实体不得免费商用”。需要明确的是：严格意义上，任何按“用户类别/行业领域”差别对待、禁止特定领域免费使用的条款，会显著降低社区接受度，并可能与 OSI 的开源定义（不得歧视任何人或领域）相冲突。也因此，SSPL、ELv2、BSL 等虽然在“限制云厂商/限制托管服务/限制生产用途”方面更激进或更商业友好，但它们要么不是 OSI 批准的开源许可证、社区争议较大（SSPL、ELv2），要么天然更偏“源代码可见/延迟开源”的商业模式，且与“强制二次分发必须开源”的要求并不完全一致（BSL）。

综合“强传染性 + 社区生态 + GitHub 自动识别展示”的落地成本，AGPL-3.0-only 是最稳妥的主许可证选择。为实现商业化诉求，行业常见做法是采用“双许可”：默认按 AGPL 开源，企业若希望闭源集成/闭源再分发/闭源 SaaS，则通过购买商业授权获得豁免或额外权限。这样可以在不牺牲开源合规与生态兼容性的前提下，形成清晰的商业转化路径：个人与开源贡献者继续享受免费与可协作的权利，而企业闭源场景则通过商业合同解决。
